The module is organized as a small CLI toolkit around one HTTP client and one fixed question schema:
- `jev_client.py` is the only network boundary: it POSTs to `https://openrouter.ai/api/alpha/decisions` with model `typesafe/jev-1.13`, reads `OPENROUTER_API_KEY` from the environment, and implements exponential backoff retries for HTTP 429/529 plus timeout handling. It exposes `ask(state, questions, timeout)` and `redact_secrets(text)`.
- `questions.py` owns the prompt contract: `JUDGE_QUESTIONS` (7 fixed questions — `literal_question`, `true_intent`, `danger_level`, `should_reply_now`, `best_action`, `she_needs`, `tension_resolved`) plus helpers `build_state(messages, relationship)` and `build_rank_question(candidates)`. Instructions/criteria are in English; chat text stays Chinese.
- `calibrate.py` is the evaluation harness: loads `fixtures/labeled_set.json`, serially runs every case through `ask`, computes per-question hit rates, confidence averages, danger-level MAE, latency and cost, then writes `report/calibration.json` and `report/calibration.md` via `redact_secrets`.
- `demo_meme.py` is a smoke test running the screenshot conversation with three candidate replies and writing `report/demo_meme.json`.
- `probe_background_field.py` is an ad-hoc wire-format probe that sends the same fixture with and without a top-level `background` field to determine whether the endpoint ignores or rejects unknown state fields.
Dependency direction is one-way: scripts → `jev_client` + `questions`; no cross-imports between scripts. The `TASK.md` file documents the protocol, acceptance gates (MAE < 1.0, intent/she_needs ≥ 60%), and iteration rules.
