Two cooperating subsystems under one package:

- `Prefs.kt` — a single `SharedPreferences` wrapper exposing typed properties for judge/reply/vision API routes, OCR engine selection, context-history toggles, overlay UI state, and hosted-gateway credentials. It owns migration (`migrateIfNeeded`, `unseedBochaDefaultIfUnconfigured`) and provider routing (`judgeEndpoint`, `replyEndpoint`, `visionEndpoint`), plus a cloud-mode override that swaps keys and endpoints when `cloudActive()` is true.
- `kb/` sub-package — a file-backed knowledge base persisted as plain JSON under `filesDir/kb` (`notes.json`, `contacts.json`, `logs/<id>.json`). `KbStore` is a singleton (`get(context)`) with a private constructor and an internal `Any` lock; every read/write goes through it, using temp-file + rename for atomicity and corrupt-file preservation. `KbModels.kt` defines the domain data classes (`Note`, `Contact`, `LogEntry`, `ChatContext`). `ContextBuilder` turns a `ChatSnapshot` into a `ChatContext` by matching contacts, deduplicating on-screen messages against stored history, keyword-matching notes, and enforcing a `BUDGET_CHARS` cost budget. `KbSelfCheck` is a smoke-test harness that runs against the real store but a scratch `Prefs` instance to validate name normalization, note matching, and history de-duplication.

Dependency direction: `ContextBuilder` depends on `KbStore` + `Prefs`; `KbSelfCheck` depends on both; `ChatModels.kt` is a leaf shared DTO layer used by callers outside this module. No external serialization library is used — `org.json` is hand-written.
