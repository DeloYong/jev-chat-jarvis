Two-layer split inside `com.jev.probe.billing`:
- `EntitlementRepo.kt` is a pure Kotlin `object` acting as the gateway client. It exposes data class `Entitlement` (with `fromJson`/`toJson`) plus functions for device registration (`register`), balance sync (`refresh`, `refreshQuietly`, `cached`), order creation (`createOrder` returning an `OrderTicket` with a browser URL), and order polling (`orderStatus`). All network calls go through `HttpJson.get/post` using `Route.CLOUD`; credentials and balances are persisted via `Prefs`. Device identity is derived from `Settings.Secure.ANDROID_ID` with a UUID fallback stored in prefs.
- `PlanActivity.kt` is the only `AppCompatActivity` entry point: it builds a scrollable LinearLayout of cards/labels programmatically, delegates every network call to `EntitlementRepo`, and on success opens the returned `payUrl` in the system browser. A background poll loop (`pollPendingOrder`) checks `/v1/orders/{id}` until status becomes `paid`, then refreshes the balance.

Dependency direction is one-way: `PlanActivity` → `EntitlementRepo` → `HttpJson`/`Prefs`/`BuildConfig`. The test file `HostedPolicyTest.kt` exercises the sibling `HostedPolicy` helper (in `core`) that decides whether hosted mode is active, which routes are allowed, and whether access is granted — keeping policy logic out of the UI.
