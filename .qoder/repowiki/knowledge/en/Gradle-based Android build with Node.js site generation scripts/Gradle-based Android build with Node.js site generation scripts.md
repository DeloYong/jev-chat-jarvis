## Build System Overview

This monorepo uses two distinct build systems:

1. **Android app** — Gradle (Kotlin DSL) via the Gradle Wrapper, building a single `com.android.application` module.
2. **Static docs site** (`site/`) — plain HTML/CSS/JS generated by Node.js ESM scripts under `site/tools/`, driven by JSON manifests.

There is no Dockerfile, Makefile, or CI pipeline in this branch; artifacts are produced locally and committed to the repo (see `apk/jev-assistant-v1.4-release.apk`).

## Android Build (Gradle)

### Key files
- `build.gradle.kts` — top-level plugin registry: `com.android.application` 8.7.3, `org.jetbrains.kotlin.android` 1.9.24.
- `settings.gradle.kts` — declares one module `:app`; repositories are centralized via `dependencyResolutionManagement` with `RepositoriesMode.FAIL_ON_PROJECT_REPOS` (subprojects cannot declare their own repos).
- `gradle.properties` — project-wide flags: `org.gradle.jvmargs=-Xmx2048m -Dfile.encoding=UTF-8`, parallel builds, build cache, `android.useAndroidX=true`, `android.nonTransitiveRClass=true`, `kotlin.code.style=official`.
- `gradle/wrapper/gradle-wrapper.properties` — pins Gradle 8.9 distribution.
- `app/build.gradle.kts` — the only application module.

### Module configuration highlights
- `namespace = "com.jev.probe"`, `compileSdk = 35`, `minSdk = 30`, `targetSdk = 35`, `versionCode = 5`, `versionName = "1.4"`.
- Kotlin/JVM target is Java 17 (`sourceCompatibility` / `targetCompatibility` / `jvmTarget = "17"`).
- NDK ABI filter restricted to `arm64-v8a` only (comment explains ML Kit bundled Chinese model ships native libs per ABI and arm64 is the only target for minSdk 30).
- Packaging uses `useLegacyPackaging = false` so `.so` files are uncompressed and page-aligned for Android 15+ mmap behavior.
- ProGuard/minification is disabled on release (`isMinifyEnabled = false`).
- Dependencies include JUnit 4.13.2 for unit tests plus `org.json:json:20240303` because the mockable `android.jar` lacks real `org.json` classes.

### Signing strategy
Release signing keys are loaded from an external properties file read via `System.getenv("JEV_KEYSTORE_PROPS")` (default fallback path `H:/android/keys/jev-release.properties`). The file contains `storeFile`, `storePassword`, `keyAlias`, `keyPassword`. If the file does not exist, the `release` signing config is not created and release builds remain unsigned. This is documented inline in `app/build.gradle.kts`.

### Hosted-mode gate
A Gradle property `-PjevCloudBase=...` (or `~/.gradle/gradle.properties`) injects `CLOUD_BASE_URL` into `BuildConfig`. When blank, hosted/paywall surfaces are hidden — the open-source build behaves identically to the released APK.

## Site Build (Node.js scripts)

The static site under `site/` has no framework; it is assembled by four Node.js ESM scripts in `site/tools/`:

- `build-guides.mjs` — reads `content/guides.json`, generates bilingual guide pages under `guides/` (one per article × `zh`/`en`), writes schema.org JSON-LD, OpenGraph/Twitter meta, canonical/hreflang links, and Umami analytics IDs selected based on the configured host (`chatjevs.com` vs `brewreel.com`). Supports `--check` mode that diffs against existing files and exits non-zero if stale.
- `build-discovery.mjs` — generates `sitemap.xml`, `robots.txt`, `llms.txt`, and the localized `index.html` / `en.html` from `index.html` + `content/guides.json` + translation dictionaries in `check-i18n.mjs`. Validates that the canonical host is one of `chatjevs.com` or `brewreel.com`.
- `check-i18n.mjs` — scans HTML for translatable strings and attributes; used as a shared library by `build-discovery.mjs`.
- `submit-indexnow.mjs` — submits URLs to IndexNow.

All scripts follow the same pattern: accept a `--check` CLI flag that compares generated output against checked-in files and exit(1) on mismatch, otherwise write the generated artifacts.

## Versioning & Artifacts

- App version is declared in `app/build.gradle.kts` (`versionCode = 5`, `versionName = "1.4"`).
- Prebuilt signed APKs are committed under `apk/` (e.g. `apk/jev-assistant-v1.4-release.apk`); `.gitignore` excludes `*.apk` except `!/apk/*.apk`.
- README.md points users to download the prebuilt APK and documents `adb install -r apk/jev-assistant-v1.4-release.apk`.
- No automated release pipeline exists in this branch — releases appear to be built locally and committed.

## Conventions Observed

- Gradle wrapper is mandatory (`./gradlew`); subprojects are forbidden from declaring repositories (`FAIL_ON_PROJECT_REPOS`).
- Release keystore credentials live outside the repository and are injected through `JEV_KEYSTORE_PROPS` environment variable pointing at a `.properties` file.
- Hosted deployment is toggled via the Gradle property `jevCloudBase` rather than separate branches or flavors.
- Site content is authored as JSON (`content/guides.json`) plus raw HTML fragments; generated HTML is committed to the repo and verified via `--check` modes in the Node scripts.
- Bilingual support (`zh`/`en`) is enforced through the i18n scanner — missing translations cause `build-discovery.mjs` to throw.
- Only `arm64-v8a` native ABIs are packaged; other ABIs are intentionally excluded.
