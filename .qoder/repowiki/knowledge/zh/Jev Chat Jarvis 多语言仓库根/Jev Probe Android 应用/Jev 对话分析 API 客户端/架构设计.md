模块按职责拆分为四层：
- 传输层 `HttpJson.kt`：基于 `java.net.HttpURLConnection` 的共享 POST 实现，负责 Bearer Token、超时、429/529 指数退避重试、异常归一化为 `ApiException`，并按 URL 注入 OpenRouter 的 attribution headers。
- 响应契约层 `ResponseShape.kt`：把 2xx 响应体进一步校验为业务成功（拒绝 200+error 体、空 content、缺失 answers 等），统一抛出带路由信息的 `ApiException`，避免“成功但空结果”的错误路径。
- 领域客户端层：`JudgeClient`（/alpha/decisions 或 /v1/systemone，7 个判断问题 + 候选排序）、`ReplyClient`（OpenAI 兼容 `/chat/completions`，生成 3 条候选回复、摘要、连通性 ping）、`VisionClient`（支持 `image_url` 的多模态转写）；三者均从 `Prefs` 读取各自 endpoint/key/model，互不依赖。
- 门面层 `JevClient.kt`：聚合 judge/reply 两个子客户端，暴露 `judge`、`draftAndRank`、`analyze` 三个高层方法，是外部唯一入口。
- 提示词/协议数据 `JevQuestions.kt`：以 Kotlin DSL (`noul`/`choice`/`score`) 构建固定的 7 个判断问题 JSON，与 Python 端 `tools/jev/questions.py` 保持字面一致。
依赖方向单向：JevClient → JudgeClient/ReplyClient → HttpJson + ResponseShape + JevQuestions；VisionClient 独立挂载在门面之外。
